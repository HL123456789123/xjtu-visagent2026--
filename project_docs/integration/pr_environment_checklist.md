# PR环境与命令检查

> 本清单用于 PR 提交人如实记录环境与命令证据。命令和工作目录以根目录 `AGENTS.md` 为准；接口以 `docs/contracts/api_v1.md` 为准。未运行的项目不得填写为通过。

## 一、开始前确认

- [ ] 已阅读根目录 `AGENTS.md`。
- [ ] 已阅读 `docs/contracts/api_v1.md` 中与本次任务相关的章节。
- [ ] 已阅读本人的个人任务计划，并确认 Owner、文件边界、优先级和交付物。

## 二、包管理器与文件边界

- [ ] 后端依赖操作仅使用 `uv`；如未涉及后端，填写“不适用”。
- [ ] 前端依赖操作仅使用 `bun`；如未涉及前端，填写“不适用”。
- [ ] 未使用 pip、npm、pnpm 或 yarn 修改项目依赖。
- [ ] 未删除、手工修改或擅自重建锁文件。
- [ ] 只有确实修改依赖时才更新依赖文件和对应锁文件。
- [ ] 未提交 `.env`、API Key、Token、`best.pt`、大型数据集或其他敏感文件。
- [ ] 未运行的测试、构建、迁移或 Docker 检查已经明确标注，没有写成通过。
- [ ] 实际工作目录、实际命令和真实结果已经记录。

## 四、提交前确认

- [ ] PR 描述中的工作目录、命令和结果与实际记录一致。
- [ ] 没有把未运行、无法运行或仅静态检查的项目写成“已通过”。
- [ ] 环境阻断已交给五天计划登记的指定 Owner，没有自行建立第二套方案。
- [ ] 接口、字段、模型输出、Recipe JSON、SSE 和错误码没有偏离 `docs/contracts/api_v1.md`。
