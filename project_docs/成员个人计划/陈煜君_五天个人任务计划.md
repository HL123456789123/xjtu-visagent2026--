# 陈煜君：五天个人任务计划（V1 执行版）

> 角色：菜谱后端与最小 LangGraph 负责人
> 唯一接口标准：`docs/contracts/api_v1.md`。发现冲突只提交问题，不得私自修改对外字段；模块内部辅助字段允许增加。

## 开始前统一原则

根目录 `AGENTS.md` 负责环境和命令，`docs/contracts/api_v1.md` 负责接口，本计划只负责任务、Owner、文件边界、优先级和交付物。后端只使用 `uv`，前端只使用 `bun`；不得擅自切换包管理器，不得删除或重建锁文件。本文保留的命令只作任务验收提示，工作目录和最终命令以 `AGENTS.md` 为准；不得声称未执行的测试已通过，完成后必须报告实际工作目录、命令、结果和风险。

Day3 和 Day4 直接在 `develop` 联调，用集成记录和对应 Commit 哈希标记阶段状态；不创建额外 `integration/*` 分支。个人临时分支通过 PR 合入 `develop` 后及时删除，`master` 只用于最终稳定版本。

已有代码先运行和核对，不直接推倒重写。对外接口与 V1 不一致时优先增加 Adapter；创新只能放在模块内部，必须可关闭或回滚，且不得阻塞 Day3/Day4。需要修改共享文件时，先向 owner 提交接线需求或取得明确授权。

## 1. 我的总体职责

按固定 Prompt 直接生成结构化菜谱，并用最小 LangGraph 完成回答或版本更新。

- 实现 RecipePreferences、Recipe、Nutrition 的 V1 Schema。
- 首次生成只走 `load_confirmed_ingredients -> generate_recipe -> validate_and_save`。
- 对话只走 `load_recipe_context -> call_llm -> answer/update_recipe`。
- 使用固定 Prompt，Pydantic 校验后通过 Repository 保存。
- 营养数据直接包含在菜谱 JSON，并固定免责声明。
- SSE 只发送 `token`、`recipe_updated`、`done`、`error`。
- 真实 LLM 失败返回 503，不自动切 Fake。
