# 刘楚涵：五天个人任务计划（V1.1 执行版）

> 角色：食物识别工作流前端
> 唯一接口标准：`docs/contracts/api_v1.md`。发现冲突只提交问题，不得私自修改对外字段；模块内部辅助字段允许增加。

## 开始前统一原则

根目录 `AGENTS.md` 负责环境和命令，`docs/contracts/api_v1.md` 负责接口，本计划只负责任务、Owner、文件边界、优先级和交付物。后端只使用 `uv`，前端只使用 `bun`；不得擅自切换包管理器，不得删除或重建锁文件。本文保留的命令只作任务验收提示，工作目录和最终命令以 `AGENTS.md` 为准；不得声称未执行的测试已通过，完成后必须报告实际工作目录、命令、结果和风险。

Day3 和 Day4 直接在 `develop` 联调，用集成记录和对应 Commit 哈希标记阶段状态；不创建额外 `integration/*` 分支。个人临时分支通过 PR 合入 `develop` 后及时删除，`master` 只用于最终稳定版本。

已有代码先运行和核对，不直接推倒重写。对外接口与 V1 不一致时优先增加 Adapter；创新只能放在模块内部，必须可关闭或回滚，且不得阻塞 Day3/Day4。需要修改共享文件时，先向 owner 提交接线需求或取得明确授权。

V1.1 多图规则：公开上传字段只使用 `images`；支持选择、预览和删除 1～5 张 JPG/JPEG/PNG，单张不超过 10 MB、整批不超过 50 MB。上传后展示全部 `images[{image_index,image_url}]`，候选 bbox 按 `image_index` 关联图片；某张为空不算失败，整批失败时不得展示部分成功。Recipe、Chat 和 SSE 不在本人任务范围内。

## 1. 我的总体职责

按 V1.1 完成多图选择、预览、删除、上传、逐图候选展示、食材编辑和确认，并保存一批图片共用的整数 `recognition_id`。

- 限制每批 1～5 张 JPG/JPEG/PNG、单张最大 10 MB、整批最大 50 MB。
- 调用同步 `POST /api/food/recognitions`，不实现轮询。
- 展示每张 `image_url`，并按 `image_index` 展示 `IngredientCandidate` 的 `display_name`、`confidence` 和 `bbox`。
- 让用户增删改食材，并按 `ConfirmedIngredient` 提交。
- 处理 401、413、415、422 和 503。
